# 功能候选清单（纯软件方向）

> 日期：2026-08-03
> 范围：不增加任何硬件，仅基于现有 WiFi + ST7789 屏幕 + UDP 栈 + Web 控制器实现。
> 用途：决策参考。选定后逐个进入实现规划。

---

## 决策摘要

按「对 Claude Code 桌面陪伴核心定位的增益 × 实现成本」排序，推荐先做：

1. **会话统计 / 专注面板** — 强化核心卖点，依赖最少
2. **通用通知 / Toast 浮层** — 多个功能的前置依赖
3. **GitHub / CI 状态视图** — 复用现有网络服务架构，对开发者黏性最高

---

## 第一梯队：强化核心卖点（Claude Code 集成）

### 1. 会话统计 / 专注面板
- **做什么**：新增一块视图，显示当前会话 WORKING 累计时长、今日总工作时长、DONE/ERROR/PERMISSION 次数、最长一次连续 WORKING 时长。
- **联动**：和现有 `SalaryCounterService`（边工作边赚钱）同源，可合并成「今天 Claude 帮你赚了多少」面板。
- **数据来源**：`ClaudeCodeService` 状态机已在跑，只差累计；持久化到 NVS。
- **成本**：低。纯软件，RAM 几乎为零（几个计数器）。
- **依赖**：无。

### 2. 通用通知 / Toast 浮层
- **做什么**：在任意当前视图上弹一条几秒后自动消失的小条幅，用于 CC 完成 / 报错 / 要权限 / 番茄到点 / 价格触发阈值。
- **价值**：现在状态变化是整屏切换，缺一个不打断当前视图的瞬时提醒。是后续价格警报、提醒等功能的前置依赖。
- **约束**：必须遵守反闪烁铁律——只画 dirty 矩形、固定字符位、不整屏 clear。
- **成本**：中。需要一个轻量通知队列 + 跨视图的浮层渲染层。
- **依赖**：无，但解锁 5、9 等。

### 3. 多会话聚合
- **做什么**：同时开多个 Claude Code 会话时，设备聚合显示「会话 A 在跑、会话 B 在等权限」，而非只反映最近一条。
- **改动**：hook 端带 session id；设备端维护一个小会话表。
- **成本**：中。涉及 `cc_hook.py` + `ClaudeCodeService` 协议扩展。
- **依赖**：无。

## 第二梯队：新信息源视图（复用 NetworkRequestGate 架构）

> Weather / Crypto / Market 已建立了「HTTPS 服务 + NetworkRequestGate + 轮播」模式，加新信息源架构成本很低。注意：JSON/XML 缓冲必须 lazy 分配、用完即释放，别常驻。

### 4. GitHub / CI 状态视图
- **做什么**：显示待 review 的 PR 数、最近 CI 通过/失败、仓库 issue 数。
- **数据来源**：GitHub API（HTTPS，过 `NetworkRequestGate`）。
- **成本**：低。同 Crypto/Market 模式，RAM 更轻（几个数字）。需要个人 access token 配置入口。
- **依赖**：无。

### 5. 价格警报阈值
- **做什么**：为 Crypto/Market 加上下限阈值，触发时通过 Toast 层弹出 + 切个表情。
- **价值**：把「被动看价格」变成「主动提醒」。
- **成本**：低（在现有服务上加阈值判断）。
- **依赖**：#2 Toast 浮层（否则只能整屏切换）。

### 6. RSS / Hacker News 滚动条
- **做什么**：always-on 桌面信息流，滚动显示新闻标题。
- **成本**：中。RSS 解析缓冲需 lazy 分配、用完即释放。
- **依赖**：无。

### 7. 纪念日 / 倒计时视图
- **做什么**：「距离某日期还有 N 天」（生日、deadline、发版日）。用户在网页配置日期列表，存 NVS。
- **成本**：低。纯软件，RAM 可忽略，和 `HolidayService` 气质一致。
- **依赖**：无。

### 8. 世界时钟
- **做什么**：多时区小屏，适合海外协作/市场时间。
- **成本**：极低。
- **依赖**：无。

## 第三梯队：连接模式与生态

> `operation_mode_service.h` 已列出 BLE / USB_CDC_ONLY / AP_ONLY 三个未实现模式。

### 9. MQTT / Home Assistant 接入
- **做什么**：设备变成 HA 传感器屏 + 被 HA 控制的实体。双向：设备显示 HA 任意传感器值，HA 能触发设备切表情/弹通知。
- **附带收益**：MQTT 不依赖 WiFi TLS 堆，能缓解纯 HTTPS 的堆内存压力（参考 2026-07-30 内存事件）。
- **成本**：高。新增 `MqttService`，需适配 HA 的 discovery 协议。
- **依赖**：无（但 #2 能让 HA 触发的通知更好看）。

### 10. 纯 USB-CDC 模式
- **做什么**：完全不碰 WiFi，「插上电脑就是 Claude Code 状态副屏」。适合不想配网/出差。
- **基础**：`cc_serial_daemon.py` 已有半边。
- **成本**：中。需补全 USB-CDC-only 状态路径。
- **依赖**：无。

## 第四梯队：收尾性事项（低工作量、该顺手做）

### 11. OTA 闭环
- `CFG_OTA_MANIFEST_URL` 还是 `example.com` 占位，`CFG_OTA_ROOT_CA` 为空。
- 搭一个 GitHub Releases + manifest 生成脚本，再锁上 Root CA，OTA 才算真正可用。
- 成本：低（脚本 + 配置）。

### 12. 设备健康视图
- `MemoryMonitor` 工具已有但没有展示视图。
- 做一块显示 heap / 最大连续块 / uptime / WiFi RSSI / 剩余 Flash 的诊断屏。
- 成本：低。

### 13. 截图端点
- 现在有 `/media/frame` 投图，没有「把当前屏幕回传成 PNG」的调试端点。
- 对开发、文档截图、像素级校验都有用。
- 成本：低-中（RGB565 → PNG 编码）。
